Adversarial review of commit 3885724 (`Add BDD wire-up`). Two enforcement claims were verified by probe; the tag one did not hold.

## Falsified

- **Domain tier**: `@skip` on a scenario still skipped it and the run stayed GREEN. The `todoTags`/`skipTags`/`failTags`/`softFailTags: []` block in `vitest.config.ts` did nothing — quickpickle merges options with lodash `defaultsDeep`, which merges arrays INDEX-WISE, so an empty list leaves every default tag in place.
- **E2E tier**: `@skip` made `bddgen` emit ZERO specs, exit 0 and print nothing — the whole BDD project silently vanished from the run. Nothing guarded playwright-bdd tags at all; the recorded "tag audit not implemented" deviation was justified by viewport routing, but the audit's other job (a closed tag vocabulary) is orthogonal to viewports and was dropped without being noticed.

## Fixed

- `tests/features/FeatureFileTagAudit.ts` + test — STATIC scan of `features/**/*.feature`, run in `npm test`, banning any tag (`PERMITTED_TAGS` is empty in this repo). Static because a removed scenario produces no failure, only an absence. Falsified against both tiers; also pins the exact feature-file list so it cannot pass by auditing nothing.
- Removed the ineffective quickpickle options block instead of leaving it lying; the `defaultsDeep` trap is recorded as a WHY-NOT in `vitest.config.ts`.
- `setupFiles` named the single step file literally, so adding a feature meant editing `vitest.config.ts`. Now `tests/domain/steps/allSteps.ts` expands `./*.steps.ts` via `import.meta.glob` (vitest does NOT glob `setupFiles` — verified).
- README: the tag rule now states what enforces it; deviations now name the missing scenario-count reconciler.

## Held up under probe

Undefined steps hard-fail in both runners (re-verified in the domain tier; `missingSteps: fail-on-gen` on the e2e side).
