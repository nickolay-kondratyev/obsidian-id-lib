All changes in `e2e/` + `scripts/`; library `src/` untouched.

- `scripts/setup-obsidian-bin.sh`: download+extract into a private staging dir and
  `mv` the finished tree into the cache. The cache key is `-x <binary>`, so a run
  interrupted mid-extract left a half-populated tree that EVERY later run reused
  as "cached" — only a manual wipe recovered.
- `e2e/obsidianHarness.ts` `killAndWaitForExit`: bail when the child has no pid.
  Node only guarantees 'error' on a failed spawn ('exit' "may or may not be
  emitted"), so waiting could hang teardown past the real launch error. Also
  settles on 'error' (ESRCH from a kill on an already-reaped child). Verified a
  non-executable OBSIDIAN_PATH still fails in ~1.5s with the actionable error.
- `e2e/obsidianHarness.ts`: `ensureDocId`/`getDocId` were two copies of the same
  page.evaluate (path resolution + not-found error + plugin lookup). Now one
  private `callDocIdService`, keyed by a `Pick<DocIdService, ...>`-derived type so
  renaming a library method fails `check:e2e` instead of throwing "is not a
  function" inside the renderer.
- `e2e/fixtures/host-plugin/build.mjs`: clean the out dir first — it is copied
  verbatim into the throwaway vault, so stale artifacts loaded as if current.
- Documented that the process-wide (and launch-wiped) vault/sandbox dirs are what
  couples the suite to `workers: 1`.

Verified: `npm run check:e2e` clean, `npm test` 69 passed, `npm run test:e2e`
3 passed, fresh-cache download path exercised end-to-end, no leftover Obsidian
processes.
