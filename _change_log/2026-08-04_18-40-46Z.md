All fixes are in `e2e/` only; library src untouched.

- `stdio: ['ignore','ignore','pipe']` — nothing read Obsidian's stdout, so a chatty
  app would fill the 64KB pipe buffer and block mid-suite.
- `spawnAndConnect` catch: was `proc.kill()` only — leaked the CDP browser
  connection and did NOT wait for exit, reintroducing exactly the sandbox-config
  write race `killAndWaitForExit` exists to prevent.
- `waitForDevtoolsEndpoint`: listeners now detach on settle and the stream is
  `resume()`d. They previously lived for the whole run, re-matching an
  ever-growing stderr string on every chunk (O(n^2)) and pinning it in memory.
- `killWithTestRunner`: spawned children do not die with their parent on Linux.
  An aborted run left a live Obsidian holding the sandbox --user-data-dir; the
  next run wipes that dir underneath it and boots a SECOND instance on the same
  throwaway vault. A stale instance from a prior run was observed live.
- `e2e/harnessSuite.ts`: both spec files had an identical, hand-rolled
  serial+beforeAll/afterAll block, with an unguarded `harness.close()` that
  would bury a boot failure under a TypeError.

Verified: `npm run check:e2e` clean, `npm run test:e2e` 3 passed, `npm test`
69 passed, no leftover Obsidian processes after a run.
