# How to publish `obsidian-id-lib` to npm

Internal runbook for releasing this package to the public npm registry, and
then switching the visit-history plugin off the git submodule onto the
published package.

The repo is already **publish-ready** — `package.json` ships a compiled
`dist/` (bundled `index.js` + `.d.ts` types), and the build/test gates run
automatically on publish. You mainly need an npm account and one command.

- `prepack` → `npm run build` (clean + emit `dist/`) runs automatically before
  `npm pack` **and** `npm publish`, so the tarball always contains a fresh build.
- `prepublishOnly` → `npm run check && npm test` runs automatically before
  `npm publish` only, so a publish with a type error or failing test is blocked.

You never have to remember to build or test — publishing does it for you.

---

## Part A — First-time npm publish

### 1. Create an npm account (one-time)

1. Sign up at <https://www.npmjs.com/signup> (or via `npm adduser`).
2. Verify your email address — **npm refuses to publish from an unverified
   account.**
3. Strongly recommended: enable 2FA for "Authorization and Publishing"
   (Account → Two-Factor Authentication). With 2FA on, `npm publish` prompts
   for a one-time code (or you pass `--otp=123456`).

### 2. Log in on this machine (one-time per machine)

```bash
npm login            # opens browser / prompts for username, password, email, OTP
npm whoami           # should print your npm username
```

### 3. Confirm the package name is free

The name `obsidian-id-lib` was unclaimed at authoring time. Re-check right
before publishing:

```bash
npm view obsidian-id-lib version   # a 404 ("not in this registry") = name is free
```

- If it 404s → the name is available, continue.
- If it returns a version → the unscoped name is taken. Switch to a scoped
  name: set `"name": "@<your-npm-user>/obsidian-id-lib"` in `package.json`
  (the `publishConfig.access: "public"` already present makes a scoped package
  publish publicly), and update the plugin's import specifier accordingly in
  Part C.

### 4. Dry-run the publish (see exactly what ships)

```bash
cd submodules/obsidian-id-lib
npm publish --dry-run
```

Confirm the file list contains **only**: `LICENSE.md` (MIT), `README.md`,
`package.json`, and `dist/` (`index.js` + the `*.d.ts` files). It must NOT
contain `src/`, `*.test.ts`, `testSupport/`, or `tsconfig*.json` — the
`files` allowlist in `package.json` enforces this (npm always adds
`README`/`LICENSE`/`package.json` on top of the allowlist).

### 5. Publish

```bash
npm publish            # add --otp=123456 if 2FA prompts and you prefer non-interactive
```

For a scoped name, if npm complains about privacy: `npm publish --access public`
(already configured via `publishConfig`, but the flag is a safe override).

### 6. Verify the published package

```bash
npm view obsidian-id-lib          # shows the published metadata
npm view obsidian-id-lib version  # e.g. 0.1.0
```

Optional deeper smoke test in a scratch dir:

```bash
cd $(mktemp -d)
npm init -y >/dev/null
npm install obsidian-id-lib obsidian
node --input-type=module -e "import * as lib from 'obsidian-id-lib'; console.log(Object.keys(lib))"
# expect: DocIdServiceDefault, DocIdValues, DocIdGeneratorDefault, ... etc.
```

## Part B — Committing the release

The published tarball is built from the working tree, but the source and the
version bump must be committed and pushed so the release is reproducible.

> **Heads-up on git state:** inside the plugin, this repo is checked out at a
> **detached HEAD** (the commit the plugin's submodule pins), which is **one
> commit behind `main`** — `main` already has the `Add MIT license` commit
> (`LICENSE.md`). The publish-prep changes were made on top of the pinned
> commit. Base the release on `main` so history stays linear and the MIT
> license isn't duplicated:

```bash
cd submodules/obsidian-id-lib
git stash                          # park the publish-prep working changes
git checkout main                  # main already has LICENSE.md (MIT)
git stash pop                      # re-apply the prep changes onto main
#   -> LICENSE.md now matches main; git shows it unchanged. Resolve trivially if prompted.
git add -A
git commit -m "chore(release): prepare npm publishing (dist build + metadata)"
git push origin main
git tag v0.1.0 && git push origin v0.1.0   # optional but recommended: tag the release
```

> `dist/` and `*.tgz` are gitignored — they are build outputs, regenerated by
> `prepack`. Never commit them.

### Future releases (version bump)

npm forbids re-publishing an existing version. For each new release, bump
first with `npm version` (updates `package.json` + creates a git tag), then
publish:

```bash
npm version patch      # 0.1.0 -> 0.1.1  (bugfix)  | minor: new feature | major: breaking
git push --follow-tags
npm publish
```

Then bump the plugin's dependency range if needed (Part C, step 2).

## Part C — Switch the plugin off the submodule onto the npm package

Do this **only after Part A succeeds** — the plugin cannot install the package
until it exists on the registry. Run everything from the plugin repo root
(`obsidian-visit-history-plugin/`), NOT the submodule.

### 1. Remove the git submodule

```bash
git submodule deinit -f submodules/obsidian-id-lib
git rm -f submodules/obsidian-id-lib        # stages removal + drops the .gitmodules entry
rm -rf .git/modules/submodules/obsidian-id-lib
rmdir submodules 2>/dev/null || true        # if now empty
```

If `.gitmodules` is left empty, `git rm` removes it; verify with
`git status`. (Keep a local clone of the lib repo elsewhere for future lib
development — deleting the submodule here does not delete its GitHub repo.)

### 2. Point the plugin dependency at the published version

In the plugin's `package.json`, replace the `file:` dependency:

```diff
-    "obsidian-id-lib": "file:submodules/obsidian-id-lib",
+    "obsidian-id-lib": "^0.1.0",
```

Remove the now-obsolete lib-test script (its tests live in the lib's own repo
now):

```diff
-    "test:lib": "npm --prefix submodules/obsidian-id-lib run test",
```

### 3. Install and lock

```bash
npm install            # resolves obsidian-id-lib from the registry, rewrites package-lock.json
```

### 4. Verify the plugin end-to-end

```bash
npm run build          # tsc -noEmit + esbuild production bundle
npm test               # full vitest suite
npm run lint
```

All must pass. (This exact flow was pre-verified against a local `npm pack`
tarball of the package before it was published, so it is expected to be green.)

### 5. Update docs referencing the submodule

Search and update the plugin's docs to drop submodule wording:

```bash
git grep -n "submodule\|file:submodules/obsidian-id-lib" -- '*.md' CLAUDE.md
```

Notably `CLAUDE.md` (the "obsidian-id-lib (git submodule …)" mentions) and
`README.md` / `docs/` should describe it as a normal npm dependency, and the
`git submodule update --init` step can be dropped from the dev bootstrap.

### 6. Commit the switch

```bash
git add -A
git commit -m "chore(deps): consume obsidian-id-lib from npm; drop git submodule"
```

## Rollback

- **Bad publish**: within 72 hours you may `npm unpublish obsidian-id-lib@0.1.0`
  (npm restricts unpublish beyond that window). Prefer publishing a fixed
  patch version over unpublishing.
- **Deprecate instead of unpublish**: `npm deprecate obsidian-id-lib@0.1.0 "use 0.1.1"`.
